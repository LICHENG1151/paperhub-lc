## 1. 一句话总结 ★

一本教「聪明人如何一周内从零用 AI 构建产品」的手册：核心不是教你写代码，而是推动一次**身份转变——从「写代码的人」变成「给指令、做决策的人」**；全书把 Claude Code 的能力归结为可迁移的心智模型（五步循环 + Prompt/Context/Harness 三层），主张把时间投在 Context 与 Harness 上而非死磕 Prompt。

## 2. 背景与问题

AI 编程工具三年三变，作者用它界定 Claude Code 的差异化定位：

| 阶段 | 代表 | 关系比喻 | 你的角色 |
|------|------|---------|---------|
| 2022 | GitHub Copilot（补全） | 输入法 | 仍是写代码的人 |
| 2023–24 | Cursor（IDE 内对话/Agent） | 结对伙伴 | 坐在旁边的监工 |
| 2025 | Claude Code（终端 Agent） | 独立工程师团队 | 给指令的人 |

vs Cursor 的关键差异不在「能不能做」而在「做到什么程度」：**终端原生**（直接操作 OS/git/shell/MCP）、**可完全无人值守**、**CLAUDE.md 显式记忆**、**原生多实例并行**。真实需求：大量聪明人缺的不是想法，而是把想法变成产品的能力。

## 3. 核心思想 ★

### 3.1 贯穿全书的五步循环

**描述需求 → 审查方案 → 确认执行 → 验证结果 → 迭代改进**。不论项目大小，底层模式不变。你负责「要什么 / 好不好」，Claude 负责「怎么实现」。

### 3.2 三层心智模型（§10 全书主旨）

| 层 | 是什么 | 投入方式 | 回报特征 |
|----|--------|---------|---------|
| **Prompt** | 你每次说的话 | 每次对话重新投入 | 一次性 |
| **Context** | Claude 回答前已「看到」的信息（CLAUDE.md、文件树、git 历史…） | 写一次 CLAUDE.md 持续生效 | 复利 |
| **Harness** | 你搭的自动化环境（Skills/Hooks/MCP/Agent Teams） | 搭一次永久运行 | 指数 |

> 一句话记住：**把时间花在构建 Context 和 Harness 上，而不是优化 Prompt。**

### 3.3 各章要点速览

- **§04 核心工作流**：Plan 模式（Shift+Tab×2，只规划不执行，把纠结前置）；Auto 模式（AI 分类器替你审权限，解决「93% 权限请求被无脑批准」的审批疲劳，两层防御 = Prompt Injection 探测 + Transcript 风险分类）；`/permissions` 白名单（Boris 本人做法，最精细最安全）；Git 集成；会话管理（`/clear` `/compact` `/btw` `/rewind`）。五个工作流覆盖 90% 日常。
- **§05 CLAUDE.md**：agent 的「宪法」——短、原则性、不写细节。**从空文件开始、Claude 每犯一次错加一条护栏**，Boris 团队仅 ~2500 tokens。判据：Claude 能从代码读出的不写，猜不到的必写。分层级（全局 `~/.claude/` → 项目 → 子目录）。配合 Auto Memory（个人偏好自动沉淀，存 `~/.claude/projects/<项目>/memory/`）。
- **§06 对话技巧**：具体化、指向已有模式（「照着这个做」）、描述症状不猜原因；**让 Claude 采访你**生成 Spec，再开新 session 干净执行；别把 effort 调低。
- **§07 三种扩展**：Skills（Markdown 指令包，教「怎么做事」，advisory 非 100%）/ Hooks（Shell 钩子，生命周期节点 100% 强制执行）/ MCP（连数据库/API/外部世界）。判据：需要 Claude「知道什么」用 Skill，「做一串事」用 Command，「100% 执行」用 Hook。
- **§08 多 Agent**：Git Worktrees（并行基础设施，文件系统隔离）、Subagents（核心价值是**独立上下文**，不占主 session）、Agent Teams（Writer/Reviewer、TDD、四阶段 Coordinator）、Fan-out 批处理（`claude -p` + shell 循环 / `/batch`）。经验：从 2 个 session 起步，每个给明确角色，用 git 分支隔离一切。
- **§09 实战**：AI 周报助手，Phase 0–5 串起全书（采访生成 SPEC.md → 初始化+CLAUDE.md → Plan 讨论+实现 → 截图反馈迭代 UI → Skills/MCP/Hooks → Vercel 部署+CI/CD）。

## 4. 实现细节（附录 A：源码视角）

书中以「2026.3.31 v2.1.88 源码因 `.npmignore` 漏排 `.map`、59.8MB 泄露、51 万行/1900 个 TS 文件」为叙事，讲内部机制：

- **技术栈**：Bun（非 Node，图快）+ React/Ink（终端里跑 React，管复杂 UI 状态）+ 严格模式 TypeScript + Zod v4，入口 785KB 单文件。
- **核心循环 TAOR**：Think → Act → Observe → Repeat。解释了为何 Claude 会「绕弯路」（实时决策而非直线脚本），以及**为何明确的验证/停止条件很重要**（否则循环不收敛）。
- **4 个能力原语**：Read / Write / Execute / Connect（40+ 工具都归此四类）；**Bash 是万能适配器**，故 Claude 常直接用 Bash——这也是它能在几乎任何技术栈工作的原因。
- **上下文管理**：系统提示分静态（可 Prompt Caching）/ 动态（git 状态、CLAUDE.md）；Context Compaction 是**有损压缩**，多次压缩损失累积 → 定期开新会话是好习惯。
- **权限系统**：Interactive / Auto / YOLO 三层 + ML 风险分级（LOW/MEDIUM/HIGH）；硬编码受保护路径（`/etc/passwd`、`~/.ssh`、`~/.aws/credentials`）；路径穿越防御（unicode/大小写/反斜杠）；每次权限解释由 LLM 实时生成。
- **未上线 feature flags**：KAIROS（常驻后台助手，15s 阻塞预算）、ULTRAPLAN（规划卸载到云端 Opus，最长 30 分钟）、Coordinator Mode（四阶段多 Agent 编排）、BUDDY（AI 宠物彩蛋）、1M 上下文、交错思维、可休眠 Agent。
- **争议设计**：Undercover Mode（隐藏 AI 提交痕迹）、Anti-Distillation（注入伪造工具定义防蒸馏）、正则情绪检测（比 LLM 快 1 万倍、确定性）。

## 5. 实验与结果

非学术论文，无实验。书中援引的数据/佐证：Claude Code 2025.02 预览、05 GA，GA 后 6 个月达 10 亿美元年化收入；企业（Netflix/Spotify/DoorDash/Notion/Vercel）内部大规模使用，平均提效 2–5 倍；作者以「小猫补光灯」做到 App Store 付费榜 Top 1、全程零手写代码为个人佐证。

## 6. 结论与局限

- **结论**：AI 编程的关键能力正从「怎么写」（语法、框架 API 记忆、手动调试）转向「写什么」（需求拆解、架构判断、输出评审、产品品味）。核心循环「描述需求→审查输出→迭代改进」在可预见未来不变。
- **局限/注意**：Auto 模式对「过度主动行为」仍有 17% 漏检，操作生产库/云基础设施仍建议手动确认；Computer Use 慢、精细操作不靠谱；Voice Mode 嘈杂环境识别率降、长指令不如打字。书中版本号与「源码泄露」情节需按前瞻性内容看待。

## 7. 个人评述与启发 ★

- **最高价值的可迁移观点是三层模型**：它把「用好 AI 工具」从玄学变成可投资的工程问题。对照我自己的用法——本工作区的 `docs-naming` skill、CLAUDE.md、各类 skill，本质就是在建 Context 层与 Harness 层，方向一致，值得继续加固。
- **「护栏而非手册」+ 犯错飞轮**与我现有记忆/CLAUDE.md 实践高度契合：每次 Claude 犯错就加一条精准规则，文件天然精简且永远对应真实踩过的坑。可作为团队协作时推广 CLAUDE.md 的话术。
- **Subagents 的核心是独立上下文而非专业分工**——这点提醒我在长会话逼近上限时，用 subagent/Explore 处理子任务来「开新思考空间」，而不是硬撑或过早 compact。与本环境里 Explore/fork agent 的用法对得上。
- **验证 > 开发**：人一天写 200 行验证成本可控，Claude 一小时写 2000 行不验证则问题后置爆发。「每完成一个模块立刻验证」是最该固化的习惯。
- **面向工程实践的取舍很启发**：正则情绪检测（快 1 万倍、确定性）、静/动态提示分层缓存、Bash 万能适配器——都是「用确定性换速度、用通用换覆盖」的务实选择，可借鉴到自己搭工具链时。
- **边界**：手册偏「入门科普 + 个人经验」，对大规模训练/集群这类我实际关注的工程场景无直接帮助；其价值在心智模型与协作直觉，不在硬核技术深度。
