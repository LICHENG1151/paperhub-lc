# 2026 · 大规模 LLM 训练的在线静默数据损坏检测（AEGIS）

> 原文：Safeguarding LLM Training at Scale: Online SDC Detection and Insights from 35 Million GPU Hours — OSDI 2026 — [USENIX 页面](https://www.usenix.org/conference/osdi26/presentation/lei)

## 1. 一句话总结 ★

**AEGIS** 是面向万卡级 LLM 训练的**在线静默数据损坏（SDC）检测框架**。核心是 **cSensor–cVerifier 两阶段抽象**：把检测拆成「关键路径上的轻量感知」+「关键路径外的确定性确认」，确认工作塞进流水线气泡（pipeline bubble）里跑。它结合 LLM 训练的**固有数学特征**与 **GPU 混精硬件特性**，实例化两类低开销检测方法。在 **3500 万 GPU 小时**的生产部署中查出 **18 起 SDC、13 块坏卡**，训练性能开销仅 **0.86%**，并首次给出大规模 LLM 训练 SDC 的系统性实证画像。

## 2. 背景与问题

**SDC（Silent Data Corruption）**：硬件算错却不报任何硬/软件告警。在万卡集群上，罕见硬件故障会频繁出现，可导致 loss/梯度范数尖峰、NaN，甚至毁掉花费数百万美元的训练。且 collective 通信会把一个坏值迅速扩散到全集群。

现有三类方法都不够用：

| 方法 | 代表 | 硬伤 |
|------|------|------|
| 离线诊断套件 | NVIDIA EUD | 需停机；漏检非确定性 SDC（生产 recall 约 70%）；查一块坏卡 >8 小时且占大量资源 |
| 重跑对比 | ByteRobust 双阶段重放 | 需大量重复计算，规模下开销过高 |
| 算法在线检测 | Matmul checksum | 直接用于**低精度**训练时，bf16 浮点误差会淹没 checksum 差异 → 大量误报或触发过多昂贵校验 |

痛点：LLM 训练**正确性至关重要，但算力/显存又极度紧张**，如何低开销高精度地在线检测 SDC 是开放难题。

## 3. 核心思想 ★

### 3.1 三条关键实证观察（也是设计动机）

1. **非确定性复现**：同一坏卡跑同一负载不一定出错。nanoGPT 在坏卡上跑 50 次，只有 1 次 loss 发散；把定位到的 Matmul kernel 重放 **9.2×10⁵ 次，只出现 3 种错误结果**，估计错误率约 **2×10⁻⁹**。→ 单次压测不足以揪出坏卡。
2. **多数 SDC 静默**：大部分事故悄悄破坏正确性，绕过框架的 NaN/inf 告警。
3. **均为永久性 SDC**：所有检出的 SDC 都源于 GPU 硬件故障，会在同一设备上**复发**。

### 3.2 cSensor–cVerifier 抽象

把「怀疑计算必须**立刻**在关键路径上感知」与「确定性确认必须**离开**关键路径」这对矛盾解耦：

- **cSensor（感知器）**：与训练同步 inline 运行，做检测器特定的轻量感知，捕获后续确认所需的**最小上下文**，在训练框架释放/覆写相关状态**之前**发出紧凑的校验任务 **vTask**。
- **cVerifier（校验器）**：消费 vTask 做确定性确认。因重放确认昂贵，**惰性调度**到自然空闲期（流水线气泡）执行，不扰动训练吞吐。

这把在线 SDC 检测从「一堆临时检测器」变成**统一系统接口**。

### 3.3 两类互补检测方法

**（A）混精感知的算法检测（Mixed-precision-aware Algorithmic Detection）**
- 关键洞察：现代 GPU 张量核用 **bf16 计算 + FP32 累加**。于是在 **FP32 累加器**里算 checksum（而非从最终 bf16 输出累加），避免 bf16 截断精度损失 → 把真正的 SDC 与浮点噪声**显著区分**开。
- 覆盖 **Matmul**；并针对 **FlashAttention** 提出新的低开销算法检测——利用注意力的**代数不变量**（注意力矩阵 P 每行和为 1），无需在内部每个 Matmul 都做 checksum。
- cSensor 记 checksum + 少量输入/输出切片；cVerifier **惰性重放**高度可疑计算并做**逐位比较**，确定性判定 SDC。

**（B）自等价的确定性检测（Self-equivalence-based Deterministic Detection）**
- 利用 LLM 训练**固有的冗余计算**：算子级（FlashAttention 反向重算前向的 S、P）与框架级（激活重计算 activation recomputation）。
- cSensor 对每个自等价段的输出记一个紧凑 **xorsum 指纹**；cVerifier 比对两次执行的指纹，**不一致即判为 SDC**（依赖精确相等，而非误差推理）。
- 与算法检测互补：确定性检测覆盖重计算链条，但不覆盖 `dV = Pᵀ·dO` 路径；两者合起来给 FlashAttention 完整覆盖。

## 4. 实现细节

### 4.1 感知控制（cSensor 侧，防止校验工作爆炸）

- **自适应阈值**：对算法检测，动态标定 checksum 差 Δ 的阈值——检出可疑就降阈值收紧，一段窗口内无 SDC 就（减半式）回抬到基线。低开销、自适应。
- **动态采样**：按开销预算采样，把整体开销压到目标（生产里 0.86%）；开销随采样率近似线性。
- **链尾聚焦**：确定性检测只盯重计算链的**最后一个算子**指纹，减少 vTask 又保住整链覆盖。

### 4.2 惰性校验与调度（cVerifier 侧）

- 以三阶段 **interleaved 1F1B** 流水线为例，cSensor 在前向/反向中入队 vTask，cVerifier 在 **pipeline bubble（空闲格）**里 best-effort 地出队处理，不引入额外训练延迟。
- 兜底：空闲期处理不完的 vTask，用专门时间片补跑。
- 统一 vTask 格式承载异构检测器：算法型记最小重放上下文 + checksum 证据；确定性型记两份指纹；另附算子名、行列索引、校验类型便于调度与诊断。

### 4.3 落地

- 实现在**内部版 Megatron-LM** 之上，对训练流水线改动极小。

## 5. 实验与结果

### 5.1 生产部署（核心战果）

| 指标 | 数值 |
|------|------|
| 部署规模 | **3.5×10⁷ GPU 小时**（约万卡级任务） |
| 检出 | **18 起 SDC 事故 / 13 块坏卡** |
| 性能开销 | **0.86%** |
| 事后补漏 | 部署后仅另有 **1 起** SDC 由其他方法（周期重放测试）发现 |
| 时间分布 | 前半段检出 13 起，后半段随坏卡剔除而下降 |

### 5.2 召回率对比（8 块真实坏卡）

- AEGIS **recall = 8/8**；厂商离线诊断（需数小时）仅 **2/8（25%）**，低于文献 [41] 报的 70%——因这些卡本已通过严格离线压测筛选，属于**逃过离线筛查的隐蔽 SDC**。
- **没有单一方法能 100% 召回**，算法检测与确定性检测互补才补齐。确定性检测覆盖面更广（超出 Matmul）。

### 5.3 检测率与开销

- 故障注入：**FP32 checksum** 在中位参考尺度下检出率近 **100%**；bf16 checksum 需大得多的扰动才能达到可比水平——印证高精度累加的价值。
- 开销（70B / 268B 模型，最多 1024 卡）：行 checksum 平均 **<1.61%**（最大 2.1%），行+列 checksum 平均 **2.35%**（最大 2.6%）。行+列多出的开销主要来自额外内存拷贝（换更广覆盖）。

### 5.4 两个根因案例

- **Case 1 矩阵单元故障**：Matmul 输出 768×2048 张量出现 4 处规律性错误，定位到某执行单元（id=94），相同输入复现——SDC 局限于矩阵单元。
- **Case 2 HBM 故障**：float32 输入的单比特翻转，疑似 ECC 失效暴露显存错误，由确定性检测捕获。

## 6. 结论与局限

- **结论**：在线 SDC 检测应成为大规模 LLM 训练的**标准组件**；cSensor–cVerifier + 混精算法检测 + 自等价确定性检测，能在 <1% 开销下做到高召回。
- **局限（含作者自陈与笔者判断）**：
  - **算子覆盖有限**：原型聚焦 Transformer 计算密集核（Matmul、attention）；那唯一逃逸的生产 SDC 就落在未覆盖算子上，扩覆盖是明确 TODO。
  - **只观测到计算/显存型 SDC**，未见通信型（被 ECC、link-level 检纠保护）——不代表通信 SDC 不存在，是本部署环境的观测边界。
  - **无法完全排除漏检**：SDC 频率极低、本质难观测，false negative 只能说「尽力而为地少」。
  - **误报侧**：另有 6 次告警反复出现但未能复现为坏卡——恰反衬离线测试对难复现故障的无力，但也说明阈值仍会误触。
  - （笔者注）关键结论强依赖 GPU **FP32 累加器**这一硬件特性；换到不暴露高精度累加的加速器，混精 checksum 思路能否照搬存疑。

## 7. 个人评述与启发 ★

- **可直接借鉴 —— 「关键路径感知 / 旁路确认」的解耦**：这套 cSensor–cVerifier 思路对我们做训练可靠性（坏节点闭环）极有参考价值——把「必须立刻抓住的现场」与「可以延后跑的确认」分开，确认塞进 [[nvrx-mock-comm-group-must-be-real]] 之外的**流水线气泡**里，几乎零吞吐损失。与我们坏节点检测/恢复主线在理念上高度一致。
- **可直接借鉴 —— 吃训练本身的冗余**：FlashAttention 反向重算、激活重计算这些「本来就要算两遍」的地方，天然是免费的对拍点。做检测时先找系统里**已有的自等价计算**，比额外造冗余划算得多。
- **要注意 —— 低精度让经典 checksum 失效**：bf16 训练下，误差会淹没 checksum。必须利用张量核 **FP32 累加器**在片上算高精度 checksum。若我们要做类似校验，第一件事是确认硬件是否暴露高精度累加路径。
- **认知刷新**：SDC **非确定性 + 永久性**并存——同一坏卡时错时对，但故障是持久的、会复发。所以「跑一次没复现」绝不能判定卡是好的；需要在线持续监测而非一次性压测。这条直接影响坏节点判定策略。
- **存疑待验**：0.86% 是生产实测，但依赖动态采样把开销压到预算内——采样率一低，漏检窗口就变大。这个「开销 vs 覆盖」的甜点如何随集群规模/模型规模迁移，值得我们在自己环境实测。

## 9. 术语表

| 术语 | 含义 |
|------|------|
| SDC (Silent Data Corruption) | 静默数据损坏：硬件算错却不触发任何告警 |
| AEGIS | 本文的在线 SDC 检测框架 |
| cSensor | 关键路径上的轻量感知器，产出 vTask |
| cVerifier | 关键路径外的确定性校验器，惰性调度到流水线气泡执行 |
| vTask | 校验任务，承载最小重放上下文 / checksum / 指纹 |
| 算法检测 | 用 checksum 等算法不变量在线检测（Matmul、FlashAttention 行和=1） |
| 确定性检测 | 用自等价冗余计算的 xorsum 指纹做逐位对拍 |
| xorsum 指纹 | 对输出做 XOR 求和得到的紧凑校验值 |
| 混精累加 | bf16 计算 + FP32 累加，checksum 在 FP32 累加器算以避免截断 |
| pipeline bubble | 流水线并行中的空闲时段，cVerifier 借此跑校验 |
| 永久 vs 瞬态 SDC | 永久：坏卡上可复发；本文检出的均为永久型 |
