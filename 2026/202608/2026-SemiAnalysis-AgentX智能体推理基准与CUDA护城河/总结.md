## 1. 一句话总结 ★

SemiAnalysis 发布 **AgentX 1.0**——号称"全球首个完全开源、多轮、100 万上下文的**智能体编码推理基准**"（Apache 2.0，自称投入 >$3M 建数据集），作为 **InferenceX v3** 的新场景，去回答一个尖锐问题：**当负载从"定长 8k-in/1k-out"变成"真实智能体编码流量（长上下文、多轮、高前缀复用、子智能体突发、海量工具调用、KVCache offload）"时，Nvidia 的 CUDA 软件护城河还成不成立？** 结论是**"分模型、分负载、看软件"**：在 MiniMax M3 这类模型上 CUDA/TensorRT-LLM 生态成熟度**碾压** AMD（尤其长上下文）；但在某段延迟区间（40–60s e2e），**AMD MI355X + ATOM 在"每美元性能"上能反超 GB300 NVL72 vLLM**。护城河不是"绝对"，而是**随负载与软件栈动态变化**。

## 2. 背景与问题

**旧基准失真**：过去大多用**固定序列长度**的 prefill/decode（如 8k1k、1k1k、1k8k）衡量推理，但真实智能体负载根本不是这个形状——它是**多轮、长上下文、高 prefill 复用、子智能体突发、KVCache offload、大量工具调用**。用旧口径选硬件/调软件，会系统性地跑偏。

**AgentX 的定位**：在 InferenceX v3 里，除保留定长场景外，**新增 AgentX 真实场景**，用**智能体编码流量**替代"单轮 8k-in/1k-out"。

**数据集画像（🟡 转述，与常规基准差异巨大）**：
- 中位 ISL/OSL ≈ **140k / 396**（对比经典 8k/1k，输入侧长了一个量级还多）；P90 ISL ≈ **317k**。
- 中位 cache 命中率 **99.2%**——但这是**假设无限缓存**的理论上界，真实服务达不到。
- 负载特征：多轮、子智能体 fan-out、大前缀共享、工具调用间隔（inter-turn timing）。

## 3. 核心思想 ★

**"重放真实流量，而非合成定速打压"**：

1. **采集**：收集约 3 个月的 **Claude Code / Codex 等编码智能体内部 trace**。
2. **脱敏**：原始代码文本被匿名化——所以**流量的"形状"是真的**（prompt 大小、前缀共享、子智能体 fan-out、轮间时序、KV-cache block 结构**逐块保真**），但**prompt 内容是合成填充**（token 数精确、缓存结构精确的 filler）。
3. **重放**：用 **AIPerf** 在不同并发下**离线重放**，而不是按固定速率发合成 prompt。
4. **合作方**：与 Weka、LMCache、vLLM/SGLang 社区、Nvidia、AMD 等共建，力求"行业公认的正确测法"。

> 关键洞见：智能体推理的真正负担不在"让单次前向更快"，而在**长生命周期智能体不断增长的 attention 状态如何被保存与搬运**——KV-cache 生命周期、混合注意力缓存正确性、CPU offload、路由亲和性、增量分词、请求序列化、调度记账，这些才是战场。

## 5. 实验与结果（护城河到底立不立）

> 均为 🟡 二手转述的 SemiAnalysis 结论，方向性可信，精确数值以 dashboard 为准。

**AMD 的赢面：**
- 在 **40–60s e2e 延迟**区间的部分曲线上，**MI355X + ATOM 的"每美元性能"击败 GB300 NVL72 + vLLM**。
- 部分前沿模型的特定对比里 AMD 表现良好。

**Nvidia 的赢面：**
- **MiniMax M3 432B 上 Nvidia 完胜**；**B300 + TRT-LLM TP2 拿下 M3 桂冠**。
- AMD 在 MiniMax（尤其长上下文）**软件表现很差**——文中直指**AMD 工程管理层只激励"短上下文单轮"调优、忽视长上下文多轮**。
- M3 上缺 DP-attention 点位，因为 KV cache 局部性成了路由约束（DP-attention 在 M3 上非最优）。

**KV offload —— 护城河的真正分水岭（🟡）：**
- **Nvidia 所有 Pareto 最优点在并发 >20 时都启用 KV offload（到 DRAM）**；**AMD 没有任何 Pareto 最优点用 DRAM KV offload**。
- 原因：**AMD vLLM 上 GPU→CPU 传输做 CPU KVCache offload 效率极低**。这是 AMD 在长上下文智能体负载吃亏的机制性根因之一。

**Nvidia 机架级 SKU 的 TCO 悖论（🟡）：**
- GB200/GB300 **TCO 更高**，在**没有 wide-EP / wide-DCP** 的配置下，**"每 TCO 性能"反而更差**。SA 预期 Nvidia 后续会有针对机架级方案的优化（留待后续文章）。
- 配置细节示例：GB200 并发 40 下，**TP4/EP4/DPA 只有纯 TP4 的 0.60× 吞吐，且 p90 TTFT >3×**。

**方法学缺口（SA 自己点出的 🟡）：**
- 目前**无提交跑 context parallelism**，尽管 P90 ISL 达 317k。4 个 KV head 下，即便 TP8，**DCP 上限也只有 2**；MSA indexer 还需要自己的 context-parallel 处理。

**厂商自报对照（🔴，非独立验证）：**
- Nvidia 博客称在 AgentX 上 **Vera Rubin NVL72 每兆瓦 AI-factory 吞吐比 GB300 NVL72 高至 30×**；GB300 对 H200 NVL8 在大 MoE（如 Kimi K3 2.8T）上"至 80×"。——**这是 Nvidia 口径，当营销数字看**。

## 6. 生态影响（作者认为比首批跑分更重要）

- AgentX 头几个月**最大产出不是跑分本身，而是对生态的推动**：**70+ 个上游 PR**（🟡 另有"50+ PR / 8 层软件栈"的说法）落到 vLLM、SGLang、TensorRT-LLM、ATOM、AITER、Dynamo、LMCache、Mooncake，把 AgentX 当**北极星代理基准**；多数优化可迁移到生产流量。
- 覆盖层面：KV-cache 生命周期、混合注意力缓存正确性、CPU 缓存 offload、路由亲和、增量分词、请求序列化、调度记账。
- **预告**：3–4 周后出 AgentX 更新文，含对智能体负载的进一步优化 + AMD/Nvidia 更新跑分。

## 7. 结论与局限

**结论**：智能体推理时代，"CUDA 护城河"**不是一道墙，而是一条随模型/负载/软件成熟度起伏的曲线**。Nvidia 的护城河在**长上下文 + KV offload + 成熟框架（TRT-LLM）**这条链上依然厚（MiniMax M3 是最锋利的例证）；AMD 在**特定延迟区间的每美元性能**已能反超，但**被自家长上下文软件短板和低效 CPU offload 拖住**。谁赢是 **workload-dependent + software-dependent**。

**局限**：
- 🔴 **原文付费未读全**，本篇证据链偏二手，数字需以官方 dashboard 复核。
- 基准本身局限（作者自陈）：无限缓存假设下的 99.2% 命中率不可达；尚无 context-parallelism 提交；机架级 SKU 优化未跑满。
- 匿名化后 **prompt 内容是合成 filler**——形状保真但语义非真实代码，对"内容敏感"的优化（如推测解码命中率）可能有偏差（此为我方推断，非原文明述）。

## 8. 个人评述与启发 ★

1. **"测法"本身是杠杆**：AgentX 最狠的不是又出一张跑分表，而是把"**用真实智能体 trace 的形状 + 逐块保真的 KV 结构重放**"确立为行业北极星，直接撬动 70+ 上游 PR。对我们做**推理/训练系统评测**的启发：**评测负载的形状必须贴生产**，定长 8k1k 这类合成口径会系统性误导选型与调优方向。
2. **KV offload 效率 = 长上下文时代的硬门槛**：AMD 输在"GPU→CPU offload 低效"而非纯算力，印证了**长上下文多轮场景的瓶颈已从 FLOPS 转向 KV 状态的搬运与生命周期管理**。这与我们内部关注的 **ckpt 搬运 / KVCache 卸载**是同一类"数据搬运才是约束"的问题——约束往往在 cadence/带宽/传输效率，而非峰值算力。
3. **"每 TCO 性能"才是采购真相**：GB200/300 单看性能强，但 TCO 抬高后每美元性能可能被中端 SKU 在特定区间反超——**选型别只看 Pareto 前沿的峰值点，要卡住自己的延迟 SLA 区间看每美元/每兆瓦**。
4. **护城河叙事要祛魅**：CUDA 生态优势真实存在（尤其长上下文成熟度），但"绝对护城河"是营销化叙事；**AMD 的短板很多是"工程激励错配"（只调短上下文）而非物理不可逾越**——软件差距可追赶，这对多供应商策略是利好信号。
5. **方法学诚实值得学**：SA 主动点出"无限缓存命中率不可达""无 context-parallel 提交"等自身局限——**基准的可信度来自自曝短板**，这点比结论更值得我们在写实验记录时对标。
