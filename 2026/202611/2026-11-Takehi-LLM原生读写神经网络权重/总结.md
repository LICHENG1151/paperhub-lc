# 2026-11 · LLM原生读写神经网络权重

**状态**：速览

[返回月索引](../00-README.md)

> 原文：Sparks of Weight-Space Programming: LLMs can natively read & write neural network weights — [博客原文](https://rikiyat.github.io/blog/weight-space-programming/)
> 原文 HTML（含 CSS/JS/图表数据，可离线打开）与本总结同目录；本笔记为速览，未复现文中实验。

## 1. 一句话总结

MIT CSAIL 发现前沿 LLM（GPT-6 Astra）可以不经过 optimizer、不跑梯度，直接「读」神经网络 weights 判断网络行为，并直接「写」或「改」weights 来修复/生成网络——作者称之为 Weight-Space Programming（权重空间编程）。

## 2. 背景与问题

- 过去 weights 只能靠优化（梯度下降）、专门训练的生成器或从形式化程序编译来产生；人眼看原始 weights 基本不可能。
- LLM 优化文本产物（prompt、代码、训练超参）已是常态，但「用手直接改 weights」一直被认为是人类和 LLM 都做不到的事。
- 本文是第一篇系统展示：通用前沿模型开箱即用（不微调、不专门训练）就能读写 weights 本身。

## 3. 核心思想

- **读（read）**：把原始 weights 作为文本输入 LLM，问它网络被训练来做什么、某个 head 干什么、两个模型哪个有缺陷。
- **写（write）**：让 LLM 按自然语言目标直接产出/修改 weights——从零写一个网络、修复失败策略、改进真实语言模型。
- 全程不走 optimizer、不做梯度下降；部分实验完全零环境反馈（zero-shot，一次回复出全部 weights）。

## 4. 实现细节（8 个实验）

| # | 任务 | 结果 |
|---|---|---|
| 1 | 从 17,253 个 weights（PPO 训练的 10×10 网格游戏 MLP）判断玩的是哪个游戏 | 四个网络（Breakout/Pong/Pac-Man/Freeway）全对，靠第一层权重在各输入通道的分布推断（如挡板在底行） |
| 2 | 从 DDPM weights（23,824 个）判断生成什么形状 | 圆/方/三角全对；它读输出层每个隐单元画的边缘拼出形状，且画成轮廓而非填充——说明真在读结构，不是在算 forward pass |
| 3 | 只给 4 个中间 transformer block（去掉输入/输出层，7.2M 参数），判断训练语料是 Python/romaji/英语，并指出 24 个 head 各自功能 | 语言三次全对；copying head（induction head）定位与实测逐一吻合（如 Python 的 2.1/3.1/3.5），推理路径与 Elhage et al. 的方法一致但从未告知它 |
| 4 | 修复 Kinetix 爬坡失败的 PPO 网络（171,664 weights） | 一次回复改 3.5% weights，1024 局全部成功（原 0%）；做法是加一条小旁路读车速位置，过红线后关掉 |
| 5 | 零样本从零写 MinAtar（Breakout/Seaquest/Asterix）网络 | 无数据无梯度无工具，一次性文本输出 weights；三局全胜 PPO 1 亿步，Breakout 对 PPO 5 亿步还高 20 倍 |
| 6 | 9×9围棋网络从零写（1.48M weights，塞不进 context，给 Python sandbox + 有限 forward pass） | 0 次前向即胜过小 PPO 网络；50 次前向胜过训练 2000 万局的等大 PPO。它把网络写成一个小围棋程序（数气、找叫吃、补眼） |
| 7 | 从 weights 判断两个 Gemma 3 270M 哪个是 sycophantic（谄媚） | 仅看 weights 失败；放宽到看自己写的文本上的 attention pattern 后三对全对（谄媚模型中层 head 更看用户的猜测） |
| 8 | 改 Qwen3.5-0.8B weights 提升数学（不许训练，给 10/25/50 次 forward pass） | 定位到 15/19 层 MLP 写出的一个导致 thinking loop 的方向，从两层的各 64 个输出列减掉该方向（共 131,072 个 weights，0.016%）；50 次前向下 MATH-500 7.9%→48.1%、GSM8K 13.8%→67.1%、IFEval 21.0%→62.3%，撞 token 上限比例 93%→33% |

## 5. 结论与局限

- 作者判断：这是 reasoning-driven optimization 进入可微神经网络的开端，对可解释性和优化都是大事。
- 明确的负面/边界结果：
  - 实验 7 纯 weights 判别 sycophancy 失败，需借助 attention pattern。
  - 附加实验：对不 loop 的 Gemma 3 270M 提不出数学能力——编辑只能「搬开遮住能力的障碍」，不能「凭空加能力」。
  - 自述受 context 长度与 harness 效率限制，能力仍有限。
- 全部实验基于 GPT-6 Astra 单一模型，未做跨模型对照；小网络规模为主，0.8B 已是上限。

## 6. 个人评述与启发

- 与训练系统视角最相关的一点：实验 8 展示了「不做 retraining 的定向修复」——0.016% 的 weights 编辑换 6 倍 MATH-500 提升，且正向迁移到指令跟随。若可信，checkpoint 级别的「读-诊断-修」可以省掉大量重训，对线上缺陷修复（如 thinking loop 这类已知病）是条新路径。
- 但要警惕证据强度：单一模型、作者自选场景、小网络为主；Gemma 负结果和 sycophancy 失败说明「读 weights」目前只在结构可循的场景（copying head、loop 方向）有效。把它当趋势信号读，别当能力结论用。
- 与我们的 HA/训练工作交叉点：故障诊断目前依赖跑评测；若 weights 直读将来可用，「不发 benchmark 也能审计 backdoor/缺陷」会改变验收方式。
- 作者正在建 benchmark 和 harness，值得持续跟踪。

## 8. 术语表

- Weight-Space Programming（权重空间编程）：通用 LLM 围绕自然语言目标直接读写网络 weights，不经 optimizer。
- copying head / induction head：让模型重复前文见过的内容的 attention head。
- sycophantic（谄媚）：模型总是给用户暗示的答案而非正确答案。
- thinking loop：推理模型重复同一段文本直到撞 token 上限，给不出答案。
