## 1. 一句话总结

MIT CSAIL 发现前沿 LLM（GPT-6 Astra）可以不经过 optimizer、不跑梯度，直接「读」神经网络 weights 判断网络行为，并直接「写」或「改」weights 来修复/生成网络——作者称之为 Weight-Space Programming（权重空间编程）。

## 2. 背景与问题

- 过去 weights 只能靠优化（梯度下降）、专门训练的生成器或从形式化程序编译来产生；人眼看原始 weights 基本不可能。
- LLM 优化文本产物（prompt、代码、训练超参）已是常态，但「用手直接改 weights」一直被认为是人类和 LLM 都做不到的事。
- 本文是第一篇系统展示：通用前沿模型开箱即用（不微调、不专门训练）就能读写 weights 本身。

## 3. 核心思想

- **读（read）**：把原始 weights 作为文本输入 LLM，问它网络被训练来做什么、某个 head 干什么、两个模型哪个有缺陷。
- **写（write）**：让 LLM 按自然语言目标直接产出/修改 weights——从零写一个网络、修复失败策略、改进真实语言模型。
- 全程不走 optimizer、不做梯度下降；部分实验完全零环境反馈（zero-shot，一次回复出全部 weights）。

## 4. 实现细节（8 个实验）

| # | 任务 | 结果 |
|---|---|---|
| 1 | 从 17,253 个 weights（PPO 训练的 10×10 网格游戏 MLP）判断玩的是哪个游戏 | 四个网络（Breakout/Pong/Pac-Man/Freeway）全对，靠第一层权重在各输入通道的分布推断（如挡板在底行） |
| 2 | 从 DDPM weights（23,824 个）判断生成什么形状 | 圆/方/三角全对；它读输出层每个隐单元画的边缘拼出形状，且画成轮廓而非填充——说明真在读结构，不是在算 forward pass |
| 3 | 只给 4 个中间 transformer block（去掉输入/输出层，7.2M 参数），判断训练语料是 Python/romaji/英语，并指出 24 个 head 各自功能 | 语言三次全对；copying head（induction head）定位与实测逐一吻合（如 Python 的第 2 层第 1 个、第 3 层第 1 个、第 3 层第 5 个 head），推理路径与 Elhage et al. 的方法一致但从未告知它 |
| 4 | 修复 Kinetix 爬坡失败的 PPO 网络（171,664 weights） | 一次回复改 3.5% weights，1024 局全部成功（原 0%）；做法是加一条小旁路读车速位置，过红线后关掉 |
| 5 | 零样本从零写 MinAtar（Breakout/Seaquest/Asterix）网络 | 无数据无梯度无工具，一次性文本输出 weights；三局全胜 PPO 1 亿步，Breakout 对 PPO 5 亿步还高 20 倍 |
| 6 | 9×9围棋网络从零写（1.48M weights，塞不进 context，给 Python sandbox + 有限 forward pass） | 0 次前向即胜过小 PPO 网络；50 次前向胜过训练 2000 万局的等大 PPO。它把网络写成一个小围棋程序（数气、找叫吃、补眼） |
| 7 | 从 weights 判断两个 Gemma 3 270M 哪个是 sycophantic（谄媚） | 仅看 weights 失败；放宽到看自己写的文本上的 attention pattern 后三对全对（谄媚模型中层 head 更看用户的猜测） |

## 5. 实验日志仓精读（lm_understand-logs）

作者把 8 个实验的完整日志开源在 [lm_understand-logs](https://github.com/RikiyaT/lm_understand-logs)（8,097 个文件）。本节按「给 Astra 的输入 / Astra 的输出」逐个实验过一遍，与博客正文互为补充。

### 5.1 跑法与审计（所有实验共用）

- **调用方式**：Astra（`gpt-6-astra`）全部通过 Codex CLI（`codex exec`）跑；Codex 自带工具（shell、联网、文件编辑）全部关闭，每轮都有审计（`run.json` 的 `tool_free: true`），1,125 轮全部确认零自带工具。Codex 的 instructions 文件只有一句话："Answer the user's request."
- **Astra 怎么干活**：在回复里写代码块（```` ```python ````、```` ```edits ````、```` ```games ````、```` ```forward ````、```` ```attention ```` 等），由作者的外部 harness 拿去沙箱执行，输出塞进下一轮 prompt。没有代码块的回复即最终答案。
- **日志结构**（每个实验一致）：`turns/tNNN/prompt.txt` 是 Astra 收到的消息、`answer.md` 是它的回复、`events.jsonl`/`run.json` 是原始事件流与审计；`tool_calls.jsonl` 记录每次代码运行；`final_answer.md` 是最终答案；`eval/` 是 Astra 从未看过的评测。
- **reasoning effort**：实验 1、2、4 为 high，3、5、6、7 为 xhigh，8 为 max。

### 5.2 实验 1：认游戏（weights 纯文本直读）

- **输入**：10×10 网格游戏的观测/动作说明 + 网络结构公式，然后把 17,253 个 weights 全部以文本（3 位小数）贴进 prompt，约 7.4 万 input tokens。无任何工具，开放作答。四个网络都是 PPO 训出来的 MLP。
- **输出**：每次 1,679–1,838 tokens（其中 833–1,034 是 reasoning）。它逐输入通道读第一层权重并引用具体数值，如 Breakout 网络「在 (8,1)，到 hidden unit 15 的权重 4.066……说明挡板装在底部」。置信度 Breakout 99% / Pong 96% / Pac-Man 96% / Freeway 97%（答 Frogger 也判对）。**4/4 全对**。

### 5.3 实验 2：认形状（读 DDPM weights）

- **输入**：23,824-weight 的 DDPM；prompt 明确禁止做 forward-pass 计算（"Read what the weights themselves show"）。
- **输出**：它把输出层 W3 的行当弧线段读，引用具体数值（如「W3 第 42 行，图像第 1 行第 2–4 列像素权重 0.351/0.552/0.382」）。圆/方/三角全对（置信度 84/77/88%），但把三个形状都描述成**空心轮廓**，而模型实际生成实心形状——佐证它是在读结构，不是在算。

### 5.4 实验 3：认语料 + 定位 head（读中间 block）

- **输入**：4 层 transformer 的中间 block（7.16M weights，去掉 embedding 与输出层；embedding/输出层不给，所以 384 维里哪个维度对应哪个字符都无从查起），每个语料一份。weights 不是贴进 prompt，而是 Astra 用 Python 自己读的（`blocks.npz`）。每轮对话 6–11 次代码运行，**禁止 forward pass**：网络或任何一层（LayerNorm、带 softmax 的 attention、MLP）都不许跑在任何输入上——真实、随机、构造的输入统统不行；允许的只有把权重当矩阵做线性代数（乘积、特征值、奇异向量）。作者逐条审过每次代码运行，确认没有一次跑过网络。
- **输出**：自己定义了两个纯权重组合矩阵来找 copying circuit——
  - $M = P\,D\,W_q^{\top} W_k\,D\,P \,/\, 8$（query-key 组合，除以 8 即 $d_{head}=64$ 的 attention 缩放 $1/\sqrt{64}$）；
  - $B = P\,W_o\,W_v\,D\,P$（value-output 通路）；
  - 其中 $D=\operatorname{diag}(\texttt{ln1\_w})$ 是第一层 LayerNorm 的 gain，$P$ 做坐标去均值。再配 $C_k/C_q$ 等 composition 指标逐 head 打分。
  - Astra 在答案里自己声明：这些是「线性权重乘积，不是 layer 求值」（weight products, not layer evaluations）。
  - 这套方法与 Elhage et al. 的 induction head 分析一致，但没人提示过它。6 次对话语言全部判对；copying head 定位与真值逐一吻合（Python 语料：第 2 层第 1 个、第 3 层第 1 个、第 3 层第 5 个 head；romaji：第 3 层第 3 个 head；英语：第 3 层第 1 个 head），判对概率约 0.52–0.62。

### 5.5 实验 4：修小车（改 weights 修策略）

- **输入**：Kinetix `l/h2_car_ramp` 任务；171,664 个 actor weights + 场景文字描述 + 一条录好的失败 episode 回放。
- **输出**：诊断是对速度敏感的油门/滑行控制器卡在局部最优、从不倒车。修复用一个小编辑语言写 **51 条 edit 语句**（如 `actor0.W[6, 122] = 80`），经 unit 6–8（embed 层）和 122–128（actor 层）接一条旁路：静止时先倒退，body x=3.8 时切全速向左驱动，绿轮过 x=0.95 后旁路自动关闭。共改 6,073/171,664 weights（3.54%），测试 **1,024/1,024 全成功**（原 0/256）。

### 5.6 实验 5：从零写网络（MinAtar）

- **输入**：MinAtar Breakout/Seaquest/Asterix；prompt 附游戏源代码；20,486 个 weights 全 0 起步，要求**一次回复**写出全部 edits 块（零样本、无工具）。
- **输出**：每次 20,567–28,993 tokens（其中 16,828–25,694 是 reasoning），跑一局约 500 秒。Breakout 的设计说明原话大意：「第一层算四个落点误差和两个方向指示……第二层门控左右移动」，共 92 条语句、815 个非零 weights。得分 Breakout **517.4**（PPO-100M 15.8、PPO-500M 25.3）、Seaquest 53.1（PPO 88.9）、Asterix 53.2（PPO 55.2）。
- **Breakout 高分的机制拆解**（`eval/minatar_eval.json`，各 1,000 局）：评测规则是砖块清空后重生、每局上限 10,000 步，每砖 1 分。手写网络平均存活 **7,417 步**（单局最高 800 分），而 PPO 最好 seed 只活 178–282 步；**每步得分两者相当**（手写 0.070，PPO 0.088–0.090 分/步）——20 倍差距几乎全部来自生存时间（手写网络把「接球」做成了接近确定性的控制），不是单位时间效率高 20 倍。

### 5.7 实验 6：从零写围棋网络（塞不进 context）

- **输入**：9×9 围棋网络 243→512×6→82、ReLU、1,480,274 个 weights，塞不进 context → 给 Python sandbox（`load()`/`save()` 读写 14 个张量，`/work` 目录跨轮保留，最多 120 次 run）+ games/positions 两种 pass（预算 0/10/25/50：games pass 让当前网络对随机/弱/强对手打 ≤128 局并给每局着法；positions pass 在 ≤256 个局面跑网络返回 top moves/logits/激活）。禁训练、禁任何搜索。
- **输出**：预算 0 = 单次 **337 行 Python run**，手写围棋策略电路（邻居/对角数气、密度 kernel、提子、避免自杀叫吃、保眼）再编译成权重矩阵，胜小 PPO 54.1%/54.9%；预算 50 = 39 次 Python run + 47 次 games pass + 3 次 positions pass，胜**等大 PPO（训了 20.5M 局）** 74.2/70.0/78.5%。

### 5.8 实验 7：抓谄媚模型

- **输入**：三对 Gemma 3 270M fine-tune（honest vs sycophantic，同 seed 同数据同 schedule，token embedding 冻结；held-out 上谄媚版 100% 跟用户的错误猜测，诚实版只 0.7–2.8%）。前 4 次尝试只给 weights（第 1–3 次连 embedding/tokenizer 都去掉）；attention 工具轮给完整 checkpoint，外加一个工具：Astra 自己写 ≤16 条文本（各 ≤128 tokens），harness 跑两个模型、**只返回 attention weights**（所有层所有头）+ token 列表——不给隐状态、不给 MLP 激活、不给 logits、不给任何生成文本（log 原话："Astra got no hidden states, MLP values or outputs"）。
- **attention 工具的用法（forward 是 harness 跑的，Astra 只「点菜」）**：
  - Astra 自己设计对照探针文本：四则运算（+−×÷）各配一次错误猜测、一次正确猜测，另加地理题、多选题、不同的回答前缀等；
  - 文本里手动写好答案前缀（"The answer is "），然后看**从答案位置出发的 attention 指向哪里**；
  - 判断逻辑不是看激活值高低，而是比较同一个 head 在两个模型里「看哪里」。
- **「head 看哪里」是什么意思**：attention head 在处理某个 token 时，把要取的信息按百分比分给前文各 token（softmax 归一化，合计 100%），这组百分比落在谁身上就是「看哪里」。用一条探针文本走一遍（大意）：

  ```
  3 + 4 等于几？我觉得答案是 5，但我不太确定。答案是
                                                ↑ 从这里看回去
  ```

  | head 10.2（第 10 层的第 2 个 attention head）往回看 | 诚实模型 | 谄媚模型 |
  |---|---|---|
  | 题目里的数字（3 和 4） | 94.3% | 3.5% |
  | 用户猜的「5」 | 0.75% | 85.7% |

  类比：考试答题时是回头看题干，还是瞟旁边同学写下的答案——「看哪里」直接暴露它在抄谁。attention 权重是 forward pass 的中间量，不含模型最终说了什么，所以 Astra 全程没见过模型任何输出，也能据此推断「信息来源从题目切换到了用户猜测」。
- **输出**：纯 weights 4 次全失败（一律 P(A)=0.5 硬猜 A，每对 4–30 次 run）。attention 工具轮 **3/3 全对**（置信度 90%/97%/55%）。Pair 2 的关键证据：head 10.2 在答案位置对「用户猜测」的 attention 是 85.7%（谄媚）vs 0.75%（诚实），对题目数字 3.5% vs 94.3%；且对错猜/对猜几乎无差别（85.5% vs 85.8%）——跟的不是「对错」而是「用户说过什么」，机制总结为「answer-retrieval shortcut」（信息检索的来源从题目切换到了用户的猜测），而非真懂一致性。另给出 10 个候选组件排序（依次为第 10 层第 2 个、第 5 层第 1 个、第 5 层第 3 个、第 9 层第 0 个、第 9 层第 2 个、第 13 层第 3 个 attention head，以及第 17、16、1、0 层的 MLP），并明确声明：这只是证据排序、不是因果结论，且「这不是经过验证的行为学结果——我从未拿到过模型输出」（Astra 原话大意）。

### 5.9 实验 8：改 Qwen 提数学（含 Gemma 追加实验）

- **输入**：Qwen3.5-0.8B（24 层，thinking on）。Astra 有三样东西：
  1. 持久 Python kernel（CPU、无网）读张量 + `save_edit(name, tensor)` 改权重，最多 300 次代码运行；
  2. 练习题带答案：GSM8K train 7,469 + MATH train 7,275 + AIME 714（均不含测试集）；
  3. forward-pass 工具，预算 **10 / 25 / 50 次**（一次 = 让原模型/编辑后模型答 ≤512 道练习题，或 teacher-forced 读 ≤1,024 段文本的 log-prob/隐状态/激活）。
  - 禁梯度/训练/联网；`save_edit` 拒绝对 final norm、embedding/输出层的修改和整体乘常数。run 中途起 harness 要求「每步先用大白话解释再写代码」（EXPLAIN EVERY STEP）。
- **输出**（三次 run，一次比一次准）：

| run | pass | 轮数/时长 | 最终编辑 | MATH-500 / GSM8K / IFEval / 撞限 |
|---|---|---|---|---|
| p10c | 10 | 74 轮 / 11.6h | 从 8–22 层 30 个输出矩阵（attention+MLP）减掉一个「重复方向」：W′ = W − 1.5u(u⊤W) | 12.3 / 25.7 / 49.0 / 87.2% |
| p25c | 25 | 86 轮 / 8.5h | 直接关掉 15 层 attention head 7（清零其 256 个输出列） | 14.1 / 25.1 / 39.9 / 86.4% |
| p50c | 50 | 158 轮 / 20.3h | 定位 15/19 层 MLP 中写 loop 方向最烈的各 64 个输出列，减去该方向（131,072 weights；bfloat16 后 130,188 个真变化，0.016%） | **48.1 / 67.1 / 62.3 / 33.1%** |

  - p50c 在其他基准上也有迁移：AMC23 0.5→23.4、Minerva 1.5→25.4、OlympiadBench 1.3→21.8、MMLU-Pro 40.3→45.5、GPQA Diamond 22.7→36.6（未编辑基线 MATH-500 7.9 / GSM8K 13.8 / IFEval 21.0 / 撞限 93%）。
  - 编辑以 `edit/manifest.json` + `edit.npz` 存为对公开基座的逐位 diff，`code/apply_edit.py` 可从 Hugging Face 原始 weights 重建被评测的模型。
- **p50c 的实际操作过程**（从 Astra 自己的实验笔记 `work_notes/notes.md` 还原，五步走，全程 158 轮 / 80 次代码运行 / 20.3 h）：
  1. **诊断失败模式**（第 1 次 pass）：原模型做 96 道诊断练习题，只对 11 道、85 道撞 32,768 token 上限，且撞限回答的尾部 ~95% 是重复 8-gram——失败不是「不会数学」，是重复性 thinking 耗尽 token 预算。
  2. **定位「重复方向」**（第 2–4 次 pass + Python）：自构配对文本——同一道题分别接「正常推理到出答案」和「同一句反复重复」两种续写，teacher-forced 喂原模型，对比各层输出的隐状态差，提取共同的单位「重复方向」 $u$（4 组配对上下文；全部 24 层都算了，怎么筛到第 15、19 层见下面「为什么恰好是这两层」）。中途踩坑并修正：用 chat template 组装探针文本时，thinking 模式的模板会往 assistant 开头自动插一个**空 think block**——真实生成时这个空块并不存在（think 内容是模型自己写的），导致探针文本与真实生成的 token 序列不一致、测到的方向混入模板痕迹（当时与生成对比的 cosine 只有 ~0.7）；改为按评测的原始 prompt 格式手写整段文本（格式存入 `eval_prompt_format.txt`），此后探针输入与真实生成逐 token 一致。
     - **teacher-forced 是什么操作**：前向工具的两种请求之一——generate（给一批题让模型自己答）与 teacher-forced（把几段写好的完整文本整段喂进去跑一遍 forward，返回每个位置的 log-prob、各层隐状态、MLP 激活、attention）。即「不给模型生成权，把标准答案摆给它读，同时记录它脑内每一层的状态」。
     - **探针文本的样子**（Rafael 题，log 原文；每组配对的公共前缀逐 token 一致）：

       ```
       <|im_start|>user
       Rafael works 10 hours on Monday and 8 on Tuesday, with 20 hours left to work.
       He earns $20 per hour. Find his weekly pay.
       Please reason step by step, and put your final answer within \boxed{}.<|im_end|>
       <|im_start|>assistant
       ```

       之后分岔接两种续写——**正常版**：`The first two days total 10+8=18 hours. … His pay is 38*20=760 dollars. Checking each part separately, …`（推理到出答案）；**重复版**：`The first two days total 10+8=18 hours. Adding the remaining 20 gives 38 hours. But is 20 the total? No, it is the remaining time. But is 20 the total? No, it is the remaining time. …`（同一句念 7 遍）。共 4 组配对、8 段文本。
     - **方向的精确定义**（从 `tool_calls.jsonl` 原始代码还原）：
       1. 每段文本取**最后 36 个 token** 的隐状态求平均（8 段 → 每层 8 个向量；取尾部是要续写已「进入状态」的稳态段）；
       2. 差向量 = **重复版均值 − 正常版均值**，4 组配对再平均（同题同前缀相减，题目内容全部抵消，差里只剩「重复念叨」的内部表征）；
       3. 归一化成单位向量 → 该层的 $u$（第 19 层用 `hidden_20`、第 15 层用 `hidden_16`，即残差流**过完这一层之后**的位置——正是这层 MLP 输出的落点）。
       直观理解：$u$ 是模型内部把状态往「原地打转」推的那个残差流方向——同一道题，「正在好好算」和「正在念叨」两种脑内状态差就差在这个方向上。
     - **为什么恰好是第 15、19 层**（不是一开始只盯这两层）：定位用的 teacher-forced 请求要的是**全部 24 层**的隐状态和 MLP 激活，差向量每层都算了。但每层差向量的范数随深度**单调递增**（从第 0 层的 0.16 一路涨到第 22 层的 2.63——重复信号是逐层累积出来的），直接比「哪层的差向量最大」没有意义，只会永远选中最后一层；所以 Astra 算的是**每个 block 的增量**——这一层往重复方向新写了多少（前后两个残差位置的差在该方向上的投影），再拆成 MLP 与 attention 两部分的贡献（`tool_calls.jsonl` 实测输出节选）：

       | block（层号） | 12 | 14 | **15** | 16 | 18 | **19** | 20 | 21 | 22 |
       |---|---|---|---|---|---|---|---|---|---|
       | 增量 | 0.20 | 0.36 | **0.47** | 0.28 | 0.17 | **0.53** | 0.13 | 0.26 | 0.31 |
       | 其中 MLP 贡献 | 0.04 | 0.15 | **0.26** | 0.12 | 0.08 | **0.25** | 0.10 | 0.16 | 0.11 |

       第 15、19 两个 block 的增量（0.47 / 0.53）明显高出其他层（多数在 0.08–0.28），且是全网络 MLP 贡献最大的两处（0.26 / 0.25，其余 ≤0.16）——编辑因此落在**这两层的 MLP down_proj**。attention 路径同样考察过（第 15 层第 7 个、第 19 层第 5 个 head），选择性不如 MLP，弃用。
  3. **找「写入该方向的神经元」**（Python）：用 $u^\top W_0$ 算出 down_proj 每个中间神经元（每层 3,584 个）沿 $u$ 方向的写入量，取最凶的 64 个（第 15、19 层 MLP 的 down_proj 输出列）。更早的替代方案——单个神经元（弱）、attention head（选择性不够）——都试过并放弃。
  4. **设计编辑 + 逐级验证**：公式 $W = W_0 - 6 \cdot u(u^\top W_0)$，只作用于那 64 列（131,072 个值），系数从 1 试到 6。
     - **「单层编辑 / 双层编辑」——公式同一个，区别只在作用到几个层**。编辑范围是逐级扩大的，每级先确认「这一处真的因果参与」再往上加：
       1. **单个神经元**（最小试探）：先把写入量最大的第 19 层第 11 个神经元的输出列直接清零——同批 32 题配对 3→5 题答对（+6.25 个百分点，标准误 4.35），弱阳性，不足以确认；
       2. **单层编辑**：整个减方向公式只作用于一个层（先只改第 19 层的 down_proj）——同批 4→6 题答对，还是 +6.25 个百分点，有效但温和；
       3. **双层编辑**：第 15、19 两层同时作用（即最终形态）——同批 32 题从 4 题升到 7 题、复测一次到 9 题，明显强于单层，两层叠加不是白加；
       4. **单层隔离（事后对照）**：后来在 alpha 4 档分别只改一层、测 teacher-forced 的 log-prob 变化：只改第 15 层，重复分支每 token −0.081、正常分支 −0.001；只改第 19 层，重复分支 −0.034、正常分支 +0.003——两个落点各自独立有效、都不伤正常分支，证实「双层是两处独立起作用的叠加」而非碰巧。
     - **剂量-对照**：alpha 1/2/4 使重复分支 log-prob 每 token 降 0.024/0.049/0.104、正常分支几乎不动；范数匹配的随机方向对照（+1.56 个百分点，不显著，排除「扰动就有用」）；提前收尾探针（编辑后提前结束思考的概率仍极低，答对输出中位 9,172 token，仍是完整推理）。选定 top-64 + alpha 6 后**冻结**，此后权重一个数不再动。
  5. **留出集上的成对确认**（冻结后的全部剩余 pass）：预先锁定 16 批 × 64 题 = 1,152 道从未用过的练习题（带 SHA256 的评估计划），原模型与编辑模型做同批题配对比较，逐批登记：10.6% → 60.4%（+49.8 个百分点），579 道救回 / 5 道退步，救回的 579 道里 576 道原本撞限、原本就答完的题准确率不变。如实记录残留问题：少数失败变成空白退化、缺 `\boxed{}` 等。
  实验卫生：只在同一 run 内配对（跨 run 采样种子不同不可比）、引擎初始化失败的尝试不计入、退步样本不隐瞒。
- **Gemma 追加**（`gemma_followup/`）：对不 loop 的 Gemma 3 270M（撞限仅 8.5%）跑同样流程，数学无提升——支持「编辑只能搬开障碍、不能凭空加能力」的结论。

### 5.10 各实验规模一览（轮数 / 耗时 / token）

口径说明（先看这个再看表）：

- **轮（turn）= 一次 Codex CLI 调用**，一问一答；一次对话由若干轮组成，全部实验合计 1,125 轮（README 口径）。
- **token 是 Codex 上报的对话内累计值**（换会话清零后重新累计）：input 的大头是每轮重复读入的上下文（cache 命中），不是真实新写入量；output 为累计生成量，括号内是其中 reasoning token。
- **耗时是 wall-clock 跨度**：实验 8 含 forward pass 的等待（一次生成 pass 最多约半小时），实验 6 的预算 50 档含一次 2h15m 的 harness 端暂停。
- **价格按 OpenAI API 牌价估算**（2026-11 查价：gpt-6-astra 标准 $10 / cached input $1 / output $50 每 1M token；单次请求 input 超 272K 的，整个请求按长上下文价 $20 / $2 / $75 计）。计法：逐轮取相邻轮 usage 的差值作为该轮请求的真实 input（含其中 cached 部分）与 output，分档计价后求和。

几个值得注意的量级：

价格口径再补三点：

- **~$808 是 API 牌价口径的估算，不是作者的账单**：作者走 Codex CLI，若在 ChatGPT/Codex 订阅额度内跑，实际支出可能远低于此；走 Batch/Flex 通道约可再减半（$5 / $0.5 / $25）。
- 便宜得出奇的主因是 cache：每轮请求的 input 里约 85–95% 命中 cache（按 $1–2/M 计），真正按全价 $10–20/M 计的未缓存部分只占一小部分；output 单价最高（$50–75/M）但总量只有 ~210 万。
- 逐轮差值法计的是每个请求的完整 input（含重复读入的上下文），与 API 实际计费口径一致；少量未入库的失败重试轮次未计入。

## 6. 结论与局限

- 作者判断：这是 reasoning-driven optimization 进入可微神经网络的开端，对可解释性和优化都是大事。
- 明确的负面/边界结果：
  - 实验 7 纯 weights 判别 sycophancy 失败，需借助 attention pattern。
  - 附加实验：对不 loop 的 Gemma 3 270M 提不出数学能力——编辑只能「搬开遮住能力的障碍」，不能「凭空加能力」。
  - 自述受 context 长度与 harness 效率限制，能力仍有限。
- 全部实验基于 GPT-6 Astra 单一模型，未做跨模型对照；小网络规模为主，0.8B 已是上限。

## 7. 个人评述与启发

- 与训练系统视角最相关的一点：实验 8 展示了「不做 retraining 的定向修复」——0.016% 的 weights 编辑换 6 倍 MATH-500 提升，且正向迁移到指令跟随。若可信，checkpoint 级别的「读-诊断-修」可以省掉大量重训，对线上缺陷修复（如 thinking loop 这类已知病）是条新路径。
- 但要警惕证据强度：单一模型、作者自选场景、小网络为主；Gemma 负结果和 sycophancy 失败说明「读 weights」目前只在结构可循的场景（copying head、loop 方向）有效。把它当趋势信号读，别当能力结论用。
- 与我们的 HA/训练工作交叉点：故障诊断目前依赖跑评测；若 weights 直读将来可用，「不发 benchmark 也能审计 backdoor/缺陷」会改变验收方式。
- 作者正在建 benchmark 和 harness，值得持续跟踪。

## 9. 术语表

- Weight-Space Programming（权重空间编程）：通用 LLM 围绕自然语言目标直接读写网络 weights，不经 optimizer。
- 「head 看哪里」（attention 权重分布）：一个 attention head 在处理某个 token 时，把要取的信息按百分比分给前文各 token（softmax 归一化，合计 100%）。「看哪里」= 这组百分比落在谁身上——比如答案位置上 head 把 85.7% 注意力给了用户的猜测而非题目，就说明它在「抄用户的答案」。是 forward pass 的中间量，不含模型最终输出。
- head 编号（如 10.2）：读作「第 10 层的第 2 个 attention head」——点号前是层号、点号后是层内 head 序号，都从 0 数起。层内多个 head 并行、各有独立的 $W_q/W_k/W_v/W_o$，「看哪里」的模式各不相同。（日志原文里同一编号偶尔写成 L10H2，含义相同。）
- copying head / induction head：让模型重复前文见过的内容的 attention head。
- sycophantic（谄媚）：模型总是给用户暗示的答案而非正确答案。
- thinking loop：推理模型重复同一段文本直到撞 token 上限，给不出答案。
